## 2. 分工

### 2.1 模块归属

按“大脑”和“手脚”切开，两人通过 `agent-core` 里的接口对接，各自的 AI 只改自己负责的目录。

| | 甲：Agent 与数据（大脑） | 乙：设备与界面（手脚） |
|---|---|---|
| **负责模块** | `agent-core`（编排器、各 Agent、Prompt、动作协议、Guard、元素列表压缩）；LLM 客户端；记忆与技能（Room）；校园信息提取与课表识别；评测 | Shizuku 接入与 shell 助手进程；UiAutomation 读界面、截图、注入输入；主屏 / 小窗 / 虚拟屏三种舞台；预览小窗；悬浮球；语音；通知监听；前台服务 |
| **负责界面** | 模型设置页、确认卡片与接管提示 | 其余全部界面：对话页、时间线、权限引导、执行位置选择器、记忆与技能页、校园面板、首页 |
| **负责目录** | `agent-core/`、`app/.../llm/`、`app/.../memory/`、`app/.../campus/`、`eval/` | `app/.../device/`、`app/.../ui/`（上面列给甲的两个页面除外） |
| **材料** | README、第三方声明、PPT 技术部分（架构、多 Agent、评测数据） | 演示视频录制与剪辑、PPT 整体设计 |

- 乙的工作量偏重设备层，虚拟屏也是风险最高的部分，所以首页、记忆页这类界面安排在 M3，那时设备层已经稳定。
- 两人都要能讲清楚 [设计文档](design.md) 第 6 节的多 Agent 主循环和 7.3 节的执行位置，评委最可能追问这两部分。

### 2.2 接口约定

两人之间唯一的“合同”是 `agent-core` 里的公共接口，**11/13 定稿**，之后修改必须双方同意：

| 接口 | 提供方 → 使用方 | 内容 |
|---|---|---|
| `DeviceController`、`Stage`、`Observation`、`RawNode` | 乙实现 → 甲调用 | 打开舞台、读取原始节点和截图、执行动作 |
| `Action`、`ActionResult` | 甲定义 → 乙执行 | 动作协议（见设计文档 6.3 节） |
| `LlmClient` | 甲实现 → 双方使用 | 对话、流式输出、图片输入 |
| `AgentEvent` 事件流 | 甲发出 → 乙展示 | 时间线、步骤卡片、悬浮球状态、确认请求 |
| `MemoryStore` | 甲实现 → 乙展示 | 记忆与技能的查询、编辑、删除 |

接口定好后，双方都可以先用**假实现**并行开发：甲用录制好的屏幕数据回放测试 Agent，不必等真机控制做好；乙用假的 `AgentEvent` 流开发时间线界面，不必等 Agent 做好。

### 2.3 协作规则

- **代码仓库**：<https://github.com/zhou-hack/enco>，两人都 clone 下来。
- **分支**：甲用 `brain/<主题>`，乙用 `body/<主题>`（AI 靠分支前缀判断自己在为谁工作）。**每天晚上至少合并一次到 `main`**，合并前本地要编译通过、单元测试通过。
- **改动接口**：在群里说一声，由改动方提交，对方确认后再合并。
- **AI 使用约定**：两人的 AI 共用根目录的 [AGENTS.md](../AGENTS.md)（编码规范、目录归属、接口约定、安全底线），再按分支读各自的角色说明：甲读 [agents/brain.md](agents/brain.md)，乙读 [agents/body.md](agents/body.md)。`.github/copilot-instructions.md` 和 `CLAUDE.md` 都指向 `AGENTS.md`，换用其他 AI 工具时也能读到。
- **读懂代码**：AI 写完的代码，自己至少要看懂主要逻辑，答辩时会被问到。看不懂就让 AI 解释，并把要点记进开发日志。
- **测试机**：两人各一台 Android 14 手机，都装好 Shizuku。
- **联调**：每个阶段最后一天下午两人一起在真机上联调、验收。

## 4. 进度保护

每个验收日按验收标准检查。**落后超过 1 天时，按下面顺序砍功能**，保证 11/22 能完成。一个人的模块落后时，另一个人优先过去帮忙，再考虑砍功能：

| 顺序 | 砍掉或降级 | 影响 |
|---|---|---|
| 1 | 表单代填 | 演示场景不受影响 |
| 2 | 选课辅助（本来就排在有余量时再做） | 无 |
| 3 | 语音的云端识别兜底，只保留系统语音识别 | 少数没有系统语音服务的手机不能用语音 |
| 4 | 悬浮球手势自定义，只保留默认手势 | 设置页更简单 |
| 5 | 通知栏停止按钮，只保留悬浮球停止 | 无 |
| 6 | 上课提醒，只保留课表识别与查询 | 校园面板少一个功能 |
| 7 | 预览小窗的“接管后继续”，接管后由用户自己做完 | 接管后不能再交回 enco |
| 8 | 系统小窗执行模式 | 只剩主屏和虚拟屏两种；不支持小窗的机型本来也会置灰 |

**不能砍**：单 Agent 手机控制、多 Agent 主循环与时间线、主屏与虚拟屏执行（含预览小窗）、悬浮球截图问 AI、记忆与技能沉淀、通知雷达。这几项是演示和答辩的核心。

## 6. 演示场景（暂定）

决赛路演只有 5 分钟，演示部分控制在 2.5 分钟以内，选 3 个场景，分别展示一个核心卖点：

1. **悬浮球 + 截图问 AI**（约 30 秒）：在群聊里看到一张活动海报，双击悬浮球问“帮我记下时间地点”，enco 写入待办。展示“随叫随到”。
2. **一句话后台办事**（约 90 秒）：执行位置选“虚拟屏”并打开预览小窗，说“看看学习通有没有没交的作业，整理好发到我的备忘录”，然后演示者继续正常刷手机。预览小窗里能看到 enco 在后台操作，时间线上能看到规划者、执行者、反思者轮流工作，中途出错后自我纠正。展示“多 Agent 自主执行，不打扰你用手机”。
3. **记忆与校园雷达**（约 30 秒）：打开校园面板，展示通知雷达自动汇总的截止事项和明天的课表提醒；再执行一次场景 2，展示技能沉淀后速度变快。展示“越用越懂你”。

每个场景都要准备备份视频，现场演示失败时立即切换。

## 8. 规范性要求（贯穿全程）

- **第三方声明** `docs/THIRD_PARTY_NOTICES.md`：谁引入依赖或 API，谁当天登记。
